1. 单点风险 0

某人一个人负责多个模块，请假就没人兜底。

建议：为这些模块指定第二负责人（backup），或把知识写进模块知识库。

2. 负责人 vs 实际处理人 0

名义负责人不一定最熟悉现网，若负责人从未实际处理过工单（owner_handled=false），可能存在沟通断层或权责脱节。

建议：把实际处理人加入升级名单，或请负责人复核这些工单的处理方式。

3. 只有聊天记录支撑的规则 0

规则所有依据均来自聊天记录，没有正式文档支撑，容易出现口头约定过时或理解偏差。

建议：把规则补进正式文档，或标为"惯例"。

4. 说法冲突 0

单值关系上同一主体出现多个互斥值，导致运维执行时无所适从、决策歧义或产生误操作。

建议：由文档维护人裁定保留哪个值。

5. 已被替代的旧规则 0

旧规则已被新规则废止，若仍残留在认知中，容易误导值班人员执行已作废的旧流程。

建议：确认旧文档已下线或加上"已作废"标记。
